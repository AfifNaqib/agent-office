# Spike S1: can cloud hook traffic reach the relay, with network-secret auth?

Branch `spike/s1` (throwaway, never merged). Worker: `spikes/s1/` (a throwaway spike Worker, called `<spike>` below, at
`https://<spike>.<your-subdomain>.workers.dev`). It stores header presence, auth scheme,
whether the Bearer equals the Worker secret `EXPECTED`, payload keys and arrival
time. Never header values or payload text. `GET /log` shows the records.

The cloud test session's hooks (SessionStart, UserPromptSubmit, PreToolUse, Stop)
send each event four ways:

| via | How | Question |
| --- | --- | --- |
| `curl` | async command hook, `curl` with no auth header | (a) does the proxy add Bearer from the network secret? |
| `http` | `http` hook (sync, 5 s timeout) | (b) same, and latency |
| `emit` | the real emit bundle (Node `fetch`) | does our script get through at all? |
| `emitproxy` | the same with `NODE_USE_ENV_PROXY=1` | is that flag needed for Node `fetch`? |

## PO steps

1. On the PC, in `C:\path\to\agent-office`: `git fetch` then `git checkout spike/s1`.
2. Make a test token (not a real secret, the Worker is deleted after the spike):
   `node scripts/gen-token.mjs` and keep the printed value open (do not paste it in chat).
3. `cd spikes\s1`, then `npx wrangler deploy`, then `npx wrangler secret put EXPECTED` (paste the token).
4. claude.ai/code → cloud environment menu → Edit:
   - Network access: add `<spike>.<your-subdomain>.workers.dev` under Allowed domains (keep "Allow package managers" ticked).
   - Network secrets: host `<spike>.<your-subdomain>.workers.dev`, header `Authorization`, value `Bearer <token>`.
5. Tell JEBON. JEBON starts a cloud session on `spike/s1` and reads `/log`.
6. After the spike: `npx wrangler delete` in `spikes\s1`, and remove the network secret and allowed domain.

## Decision rule (plan)

- (a) works: primary design (emit sends no credential).
- Only (b) works: design change, needs PO approval (latency).
- Neither: fallback `AGENT_OFFICE_INGEST_TOKEN` env var sent as a header (weaker).

## Results (2026-10-25, cloud session on `spike/s1`, Node v22.22.0)

**Verdict: (a) works → primary design stands, with one change to emit.**

| via | Arrived | Bearer added | Matches EXPECTED |
| --- | --- | --- | --- |
| `curl` (async command hook) | yes, all 4 events | yes (see note 1) | yes |
| `http` hook (Claude Code's own client, axios) | yes | **no** | n/a |
| `emit` (Node `fetch`, no flag) | yes | **no** | n/a |
| `emitproxy` (`NODE_USE_ENV_PROXY=1`) | yes, all 4 events | yes | yes |

1. The very first `SessionStart` curl (before `scratchpad_dir` appears in the payload) came without the header. The second `SessionStart` and every later event had it. So one early event per session may be rejected by the relay. Accept, or let the relay take `session.start` without auth (no: write-only token stays required; losing one start event is fine because the next event creates the session).
2. Node `fetch` ignores `HTTPS_PROXY` unless `NODE_USE_ENV_PROXY=1` or `node --use-env-proxy` (both checked on 22.22). In the hook environment it then goes out directly and the network secret is NOT added. In this dev sandbox plain `fetch` fails with ENOTFOUND.
3. `http` hooks bypass the proxy too, so (b) is out.
4. Cloud `session_id` in the hook payload is a UUID; `CLAUDE_CODE_REMOTE_SESSION_ID` is `cse_...` (S2 cloud).
5. Latency: all four ways arrive within ~0.5 s of each other; no measurable cost for async curl.

**Change needed (V1-06, architect to confirm):** in cloud mode emit must send through the proxy. Options: (i) emit re-runs itself once with `NODE_USE_ENV_PROXY=1` when `HTTPS_PROXY` is set and the flag is off (~50 ms, cloud only); (ii) the hook command passes `--use-env-proxy` (breaks on PC Node older than 22.21, and repo hooks run on the PC too); (iii) emit opens a CONNECT tunnel to `HTTPS_PROXY` itself with `node:http` + `node:tls` (no flag, more code). Recommended: (i).

The spike Worker `<spike>` is still deployed; delete it with `npx wrangler delete` in `spikes\s1` and remove the network secret + allowed domain, or keep them until V1 replaces them.
